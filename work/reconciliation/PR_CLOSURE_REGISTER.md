## 5. Protocole de Suppression Sécurisée des Branches Distantes

### 5.1 Objectifs et Invariants de Sécurité

La suppression des branches distantes permet d'assainir le dépôt GitHub `tobianahillel-afk/cmdr` et d'éliminer la confusion créée par ~240 branches obsolètes, tout en garantissant un niveau de sécurité maximal :
- **Invariant 1 — Sauvegarde Complète & Immuable** : Aucune branche distante ne doit être supprimée tant que son dernier commit n'est pas soit (a) présent dans l'historique de `main`, soit (b) explicitement pointé par l'un des 21 tags `backup/*` immuables.
- **Invariant 2 — Non-Répudiation des Preuves** : Les registres `work/reconciliation/prs.json`, `PR-RECONCILIATION-MATRIX.md` et `PR_CLOSURE_REGISTER.md` conservent les SHAs exacts de chaque PR pour consultation médico-légale à tout moment.
- **Invariant 3 — Branche Maîtresse Protégée** : La branche `main` est protégée contre toute suppression ou réécriture d'historique destructrice (`force-push`).

### 5.2 Liste de Contrôle Pré-Suppression (Checklist)

Avant de lancer la suppression d'une liste de branches distantes, l'administrateur du dépôt doit exécuter les vérifications suivantes :
1. [x] **Vérification des tags distants** : S'assurer que les 21 tags sont bien présents sur `origin` via `git ls-remote --tags origin`.
2. [x] **Vérification de la CI sur `main`** : Confirmer que la suite complète de CI est au vert sur `main` au commit `67d40f78`.
3. [x] **Vérification de l'intégrité architecturale locale** :
   - `tools/cmdr-dev doctor` (`healthy=true`).
   - `tools/cmdr-dev validate-manifests` (204 manifestes valides).
   - `tools/cmdr-dev architecture-audit` (17 frontières conformes).
   - `git diff 82e630fce3a7f6236e03709116eca6dd0a1acd40 -- cmdr-product-spec` (0 octet).

### 5.3 Procédure Opérationnelle d'Élagage (Commandes)

#### Étape 1 : Synchronisation Locale des Références et Tags
```pwsh
# Récupérer toutes les références et les tags distants
git fetch origin --tags --prune
```

#### Étape 2 : Vérification d'Ancrage d'une Branche avant Suppression
Pour toute branche `$BRANCH_NAME` candidate à l'élagage, vérifier qu'elle est couverte par un tag ou par `main` :
```pwsh
$branch = "feature/e10-inv-120a-cross-case-tex"
$sha = git rev-parse "origin/$branch"
# Vérifier si le SHA est ancêtre de main ou contenu dans un tag
$isAncestor = git merge-base --is-ancestor $sha main; $LASTEXITCODE -eq 0
$tags = git tag --contains $sha
if ($isAncestor -or ($tags.Count -gt 0)) {
    Write-Host "Branch $branch (SHA: $sha) is safely preserved. Safe to delete." -ForegroundColor Green
} else {
    Write-Host "WARNING: Branch $branch is NOT in main and NOT tagged! Do not delete!" -ForegroundColor Red
}
```

#### Étape 3 : Suppression Sécurisée de la Branche Distante
Une fois l'ancrage confirmé, la branche distante peut être supprimée en toute sécurité :
```pwsh
git push origin --delete $branch
```

#### Étape 4 : Suppression en Lot des Branches Obsolètes Validées
Exemple de script PowerShell pour supprimer de manière automatisée et contrôlée les branches distantes vérifiées :
```pwsh
# Exécution sécurisée pour les branches de PRs fermées et sauvegardées
$branchesToDelete = @(
    "chatgpt-access-test",
    "tmp/phase4b3b2-dissemination-build",
    "tmp/phase4b3b2-lifecycle-build",
    "tmp/phase4b4a-boundaries-20260806",
    "tmp/phase4b4a-scope-iam-audit-20260",
    "tmp/phase4b4a-workloads-data-202608",
    "tmp/phase4b4a-correlation-provenanc",
    "tmp/phase4b4a-traceability-quality-",
    "tmp/phase4b4a-post-publication-veri"
    # ... étendre selon le registre prs.json
)

foreach ($b in $branchesToDelete) {
    $remoteExists = git ls-remote --heads origin $b
    if ($remoteExists) {
        Write-Host "Deleting remote branch: $b..."
        git push origin --delete $b
    }
}
```

### 5.4 Procédure d'Urgence en Cas de Restauration Requise

Si une branche supprimée par erreur devait être reconstituée à des fins d'analyse ou d'audit spécifique, elle peut être instantanément restaurée à partir de son SHA immuable consigné au tableau de la Section 4 ou de son tag de sauvegarde :
```pwsh
# Restauration à partir d'un tag de sauvegarde
git push origin refs/tags/backup/pre-consolidation/pr044-hunt-cli-f678ee1:refs/heads/feature/e10-inv-120a-offline-hunt-cli

# Restauration à partir d'un SHA consigné au registre
git push origin <commit_sha>:refs/heads/<branch_name>
```
