# E10-CMD-106O-NEXTACTION — Read-only authorized next action

## Canonical gap and actual delivered behavior
CAP-CMD-106 Incident Coordination requires a **next action** with operational owner and impact. In the preexisting local Incident Detail page, the Command owner exposed Title, Priority, Severity and BusinessImpact but **next action was always marked unavailable**, even if that same authorized owner was able to provide it. CMD-IWQ-006 requires transparent Partial state and fresh owner permission. This increment extends the EXISTING owner read projection with two optional bounded fields: `NextAction` and `NextActionDueAt`. The existing `/command/incident-detail?incident=...` server-side HTML page now shows the trusted next action and deadline only after its existing Incident List/CanRead+selected identity check and optional Command overview owner authorization. The missing optional action remains explicitly unknown and a missing deadline remains unasserted, never a claim that there is no obligation.

## Trust, error and data semantics
The browser never sets principal/tenant/environment, scope or next-action permission. The existing `IncidentOverviewOwner.ReadAuthorizedIncidentOverview` is called with the trusted host session and authenticated selected Incident; the returned IncidentID, tenant, environment and source identity/version/time are revalidated. New text <=256 bytes, valid UTF8 and no control characters. Optional deadline is <=64 bytes RFC3339Nano, nonzero, accepted only when a real action exists. Invalid/cross-scope source yields generic 503 **before any HTML is written**. HTML rendering relies on existing html/template autoescaping, CSP default-src none and no-store. No extra owner call, new engine, third-party dependency, HTTP route, source read right or mutation. The action is read-only source metadata, **not** a created Command Task, Govern Action Request, Decision or guaranteed next outcome. Time may be past; a timestamp is not evidence an action was executed.
