## Actual integrated behavior

A visible currently authorized CAP-INV-002 Search result opens the existing CAP-INV-004 Inspector through real Node fetch → Go HTTP host. The Inspector's native DOM text-only read view can offer explicit controls for uniquely attributed *visible* source, normalized or enrichment field-value pairs (no raw-derived controls when raw denied). Clicking invokes an optional JS journey `draftPivot(field,value)`: a separate fixed same-origin POST `/investigate/event-inspection/pivot` with the selected Event/tenant/environment/Job/run/correlation/source and the **current Search Job's time window**. The server reauthorizes Search Job/Event and separate PivotAuthorizer, enforces exact presence and unambiguous source provenance, applies Inspector bounds, and returns an **unexecuted** Query draft with source, time, lineage and server-owned return origin. Browser validates all those invariants and rejects a forged origin; no client permission bit or arbitrary URI is allowed. All fields and draft summaries render with textContent; no search automatically executed or stored. A second visible-but-action-forbidden field is denied. Return/back and cancellation preserve the old Search window only when the same owner-authorized Job/run still exists.

The synthetic loopback fixture uses a random per-test bearer and independently scoped SessionResolver, SearchOwner, TelemetryOwner and PivotAuthorizer. It is **not a production IAM/provider, field metadata classification, CSRF/TLS, query executor, audit persistence, multi-tenant deployment or runtime browser**. `auditRequired:true` signals an obligation; it is not an emitted durable audit event. Raw payload, denied/foreign metadata and backend refusal details are not transmitted to browser.
