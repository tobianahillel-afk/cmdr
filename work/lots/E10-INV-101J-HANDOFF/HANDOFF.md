## Canonical requirement vs implementation
- **Before:** native owner-authenticated GET Case Queue returned a permission-scoped projection supporting `q/status/owner/freshness/sort`, but had no native selection/navigation response. Independently, the first-party `OpenCaseWorkspace` and `RestoreCaseQueue` routines already handled bounded navigation, filter-aware selection, changed permission and stale state.
- **After:** the very same authenticated native GET permits optional `open_case=OPAQUE_ID` and `scroll=NONNEGATIVE_INT`, alongside the existing query controls. It performs the exact existing full Case, Incident and Finding server object-read checks **before** any filtering or handoff. Only a currently filter-visible, non-stale Case can yield the existing `WorkspaceHandoff` JSON, screen `INV-CAS-001`, updated-at and transient return token. `OpenCaseWorkspace` is the only transition engine; `RestoreCaseQueue` independently reauthorizes later. An opaque Case ID is preserved including leading/trailing spaces, so no accidental selection pivot.
- The optional scroll requires selection. The request remains GET-only, no-store/no-referrer/Vary Authorization and generic on denied/malformed selection. Limit raw URL query to 4096 bytes, at most 7 unique keys, each filter/search bounded per existing contract, open Case ID at most 1024 bytes, scroll bounded by the original `maxReturnScroll`.
- No source record, Incident, Finding, bearer, real IAM authority, persisted Saved View or Case mutation is embedded in the navigation token. **Base64 is neither encryption nor a signed permission grant**. Never store/share it as a credential.

## Proof plan, limits and release
- Go HTTP integration tests: already authorized exact Case ID with whitespace, full existing status/owner/freshness/search/sort plus scroll -> correct `WorkspaceHandoff`; return state restores under current rights and rejects changed permissions. Independently authorize *all* provider candidates, including a denied Case with search-matching title; no denied metadata in response.
- Negative: denied Case, stale Case, filtered Case or nonexistent ID returns generic failure with no navigation token; invalid/duplicate/unknown tenant/permission/origin or malformed scroll/ID rejected **before** contacting session/provider/authorizer.
- Legacy authorized GET with no Case selection still returns the existing native projection. No new runtime dependencies, migrations, cookie/identity backend or API costs.
