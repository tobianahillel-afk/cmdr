# E10-CMD-106D-NAVIGATION — Incident-linked Case read-only navigation

## Canonical requirement and ownership
CAP-CMD-106 Incident Coordination §§9,11,17,21 and CAP-CMD-101 Unified Work Queue §§9,11,17 require that authorized linked Investigate Case can be navigated from selected Command Incident. CAP-INV-110 owns the destination Case Timeline read path. The Case belongs Investigate, the relation belongs Shared Object Linking, Incident belongs Command. Engineering parent E10-CMD-106; this is task D, depends on C-FRESHNESS IMPLEMENTED, which itself depends on B-SOURCEJOIN implementing *independent* link and Case authorizations. Git parent #179 SHA `42acd54cd3601f6ea02cd67bd62ae832eb682d28` is distinct from engineering parent.

## Real change and limits
The **existing** server-rendered `GET /command/work-queue` HTML selected-Incident section now emits a fixed first-party read-only link `/case-timeline?case_id=<query-escaped-authorized-ID>` for each Case that passed Shared Link + Investigate Case checks. URL has **no** client-controlled tenant, environment, token, raw field, status permission or arbitrary destination. html/template does built-in `urlquery`; test includes a hostile ID containing ampersand and fragment. The destination's **existing** `CaseTimelineHTTPHandler` independently authenticates the session and authorizes Case/Timeline Entry/typed source on *every* request; opening a link confers no extra rights. Existing Command JSON remains unchanged. Links do not appear for Task, no selected Incident, unknown/denied/unreadable linked Case.

This is **only a navigation pointer** that becomes operable when an application host deploys both existing read-only handlers under the same origin. A standalone Work Queue server with no mounted `/case-timeline` returns 404. The target currently returns a read-only JSON Timeline, not the full native analyst workspace, and this increment does not deliver exact return-to-Incident restoration. Consequently this is a bounded step toward, **not acceptance** of, the complete CAP-CMD-106 `Open in Investigate` journey.

No new authorization engine, backend route, database, migration, mutation, Class-2 Case creation/link, cross-tenant privilege transfer, reusable navigation ticket, external API, third-party library or production IAM. No assumption that a simulated provider constitutes deployed integration. OPEN-013 remains open.
