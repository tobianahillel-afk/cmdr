## Implemented behavior and trust boundary
An already owner-authorized Command selected Incident emits an HTML Case link with `origin_incident=incident-a`, derived from the **Command selected source record**, URL-encoded. Investigate accepts exactly one nonempty <=128-byte UTF-8 printable origin as a read-only HTML navigation hint only; rejects origin under JSON (legacy strict API), extra owner/scope/permissions, duplicates, malformed percent/UTF8/control/whitespace and excessive lengths. It is NOT an Incident authorization grant, and its ID is NOT used in Investigate's Case, Timeline Entry, typed source or source.read checks. Only after actual Case authorization does Timeline HTML show fixed relative `/command/work-queue?view=incidents&selected=Incident:ID` (encoded) as explicit return. Each page and filtered Timeline link carries the same bounded hint; existing source-preview `return_to` validation allows only one such bounded hint nested in its same-Case fixed `/case-timeline` URL. After independently authorizing source.read, source HTML returns to the original filtered/paged Case read, which provides the Command return. The actual Command route rechecks its own session and Incident owner on return. The Command-only principal still gets Case denial, despite being authorized for the Incident. No arbitrary URL/host, new endpoint, cookie, shared permission or query engine.
