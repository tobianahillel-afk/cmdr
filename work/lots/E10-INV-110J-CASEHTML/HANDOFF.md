# E10-INV-110J-CASEHTML — Owner-authorized browser Timeline

## Functional gain
Previously the real Command selected Incident to linked Investigate Case hyperlink returned only JSON at /case-timeline. An analyst following that link in a browser had no readable Timeline. The existing API now content-negotiates static read-only HTML for Accept:text/html and retains the existing byte-compatible JSON schema for API clients. HTML shows source-authorized entry ID, kind, source time, timezone/uncertainty, source reference, provenance, version, and supersession state. Superseded appears only for a source-authorized successor in the full visible cohort, before pagination; false/absent means NON DETERMINÉ, never assertion of a current version. No made-up source open link.

## Real HTTP behavior
The same-origin Go router already serves GET /command/work-queue and GET /case-timeline. Command source-owner authorizes link for selected Incident. Following it in a browser independently authenticates Investigate and rechecks Case, each Timeline Entry and typed owner; no Incident.read is promoted into Case.read. HTML variant uses identical Project, authorization, filter and page routines. Default HTML page <=50 rows; explicit limit <=200. Next/prev links carry only validated case_id/kind/q/from/to/limit/offset selectors, NEVER principal, tenant, environment, bearer token or permissions; reauthorization occurs on EVERY request. html/template autoescapes untrusted source metadata; CSP default-src none, form-action none, no-store, nosniff, no-referrer. No source access without owner-specific permission.
