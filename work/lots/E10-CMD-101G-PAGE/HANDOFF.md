- **Code owner:** `product-runtime/work-queue` (Go), reusing existing exact six-view Project and one authenticated `GET /command/work-queue`, first-party `SessionResolver` and per Incident/Task `Owner.CanRead`.
- **Former behavior:** 5000 candidates scanned and individually authorized, sorted, then only first 50 accessible. No HTTP or HTML mechanism to retrieve the remaining authorized rows.
- **New Class-0 behavior:** page-1 (without a cursor) remains <=50 and keeps the established `first-page-only` diagnostic when truncated, but supplies optional `next_cursor` when more rows exist. A subsequent GET with `cursor=...` re-resolves the current host session, runs EXACT SAME bounded owner List and authorization on EVERY in-scope object, filters and sorts deterministically, recomputes a SHA-256 revision from **only fully owner-authorized rows and request principal/tenant/environment/view/status/sort**, and exposes the next 50 only if the submitted opaque cursor matches that current revision. Revoked/changed/foreign cursor = generic 404, no partial rows; malformed/duplicate/oversized cursor = 400 before session and provider. The cursor contains just a 1-version/offset/hash presentation hint, NOT raw IDs, bearer, tenant scope or permissions; it is **not signed** and does **not confer authority**. Selection of an Incident/Task only succeeds if it belongs to the currently visible freshly authorized 50 rows. Same-route HTML includes safe escaped **Page suivante** and **Première page** links preserving view/status/sort, without JavaScript or a second queue screen.
- **Bound:** maximum owner 5000 candidates, O(n) bounded revision construction per GET, 50 rendered rows, no new Owner or third-party call, no paid API. Changes in source data/health across page reads may stale a cursor by design: not a transactional snapshot, no final cursor standard or zero-cost deep paging.
- **Absent/remaining:** Shared Saved View persistence and projection, real IAM/source provider, final Inspector/Incident Detail and linked Case/Run navigation, persistent cursor or host-backed revision, stable scrolling, canonical schema/version decision, full CAP-CMD-101 acceptance and production launch.
