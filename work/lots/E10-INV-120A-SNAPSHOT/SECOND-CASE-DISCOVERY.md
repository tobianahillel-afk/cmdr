The functional PR #41 already provides a local operator-selected Case/Timeline/typed-source journey and a two-Case comparison, but the second Case required manual ID entry even after server-authorized Case discovery. This change reuses the existing authenticated GET /demo-cases response to populate BOTH selectors. The comparison then re-fetches BOTH Case timelines through existing server-side Case, Timeline Entry and typed-source checks. No new endpoint, provider, authorization model, database, framework or dependency is added.

Equal Case IDs still fail the existing comparison validation.
