# E10-INV-120A — browser-integrated authorized cross-Case chronology export

Functional capability: the existing loopback analyst UI now offers a separate explicit **sensitive JSON event chronology** download after TWO complete, independently source-authorized Case timeline traversals. This bridges the already working browser aggregate comparison with the existing CLI-only detailed event export. It does not call a new API or reimplement tenant/source authorization.

Reuse-first decision: native browser Blob and existing `/case-timeline` page/pagination/permission path plus Go first-party owner snapshot, no new datastore, generic query/index abstraction, IAM layer or third-party dependency. An external search index/DB would add state and authorization hazards not needed for two <=5000-entry snapshots.

The opt-in output holds only the server-projected Case-scoped entry ID, kind, source time/timezone/uncertainty, source reference, provenance, version and permitted supersession; it does NOT include the bearer, tenant, typed source preview, raw source payload or destination URL. Certain instants sort chronologically; uncertain timestamps follow. Each Case can have 5000 entries; receipt is capped at 16 MiB. Unknown mandatory metadata disables sensitive export without blocking the preexisting aggregate comparison. Source reference matches across Cases do not establish real-world identity.

Security: this remains a **synthetic loopback demo**. Existing server handlers evaluate Case, Timeline Entry and source access for each page. No browser-supplied tenant or ACL flags. The button stays disabled until both complete; any token/Case/filter change, abort, refusal or inconsistent pagination clears the prepared receipt. The user must click to write locally and must protect the file thereafter. No automatic save, remote upload, cryptographic custody, real production IAM, transactionally consistent multi-Case snapshot or signature; OPEN-013 remains open.

Acceptance: Node VM tests exercise 205+3 authorized entries across three pages, deterministic known-vs-uncertain chronology, explicit click/download/revoke, no bearer/preview, denied second Case, invalid metadata, token invalidation. Go/Node CI is the authority for actual executed results; do not claim success before exact-SHA GitHub Actions. This is a material analyst-visible integration increment, not a cosmetic test/validator change.
