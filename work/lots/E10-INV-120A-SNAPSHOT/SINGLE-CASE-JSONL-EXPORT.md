# E10-INV-120A — authorized single-Case JSONL export

Functional analyst workflow: `go run ./cmd/case-timeline-demo -principal=analyst-a -snapshot=/absolute/path/owner.json -export-case=case-a > authorized-case.jsonl`.

The first record is a metadata object (`format=cmdr-local-case-timeline-jsonl-v1`, Case ID, visible entry count, visibility status, `synthetic=true`), followed by one `timeline-entry` JSON object per independently authorized event. This allows ordinary local `jq`/Python/DFIR streaming analysis without a custom index, query language, persistence engine, paid API, or new Go dependency. Reuse the already existing `collectDemoCaseTriageWithObserver` authenticated Case discovery and 200-entry page traversal through the same server-side Case/Timeline/typed source authority.

An operator supplies a bounded local JSON owner dataset and a synthetic principal. No browser permission flags, direct snapshot field reads, or unverified source rows become export authority. The code buffers all authorized records and validates every page/entry before emitting a single byte; a denied second tenant, malformed dataset, cancellation or inconsistent pagination produces no receipt. Max 5000 entries; max 16 MiB generated JSONL. Token, raw source previews, other tenants and denied sources must not be exported.

The output is **sensitive, unsigned and synthetic**. Operator dataset and principal are **not production IAM**. This is not a trusted SIEM provider, evidence custody signature, immutable consistent snapshot, live ingestion, production-ready backend or proof of OPEN-013 closure. Protect any redirected output and do not use customer data with the local demo. Functional acceptance requires an actual on-disk >200-row source dataset, one complete JSONL receipt with observed/inferred rows, no hidden sources, and no byte emitted on a denied/cancelled/invalid run. Exact GitHub CI and a single independent risk-based L2 must check the final published functional snapshot.
