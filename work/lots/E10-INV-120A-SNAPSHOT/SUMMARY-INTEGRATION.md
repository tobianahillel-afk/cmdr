# E10-INV-120A — authenticated multi-page Case investigation summary

**Functional user value.** The operator-selected JSON Case owner snapshot can now be examined by an analyst in one loopback workflow: authenticate with the local ephemeral bearer, discover Cases, select a Case, filter a Timeline, inspect individually authorized source previews, and choose **Analyze authorized events**. The view walks all allowed HTTP pages (up to 5,000 entries, 200/page), reports exact counts by five event kinds and unknown-time count, and does not cache bearer credentials or hidden source data.

**Reuse-first decision.** Reuse the existing authenticated, owner-ACL-enforcing `/case-timeline` API and browser-native `fetch`/`AbortController` and Go+Node tests. Do not invent a second authorization framework, analytics database, new server-side aggregated endpoint, custom storage or third-party index for this bounded local demonstration. Count only already authorized rows. Treat an inconsistent total, duplicate ID or malformed/incomplete page as a failed summary, never a partial success. Changing Case/token/filter cancels pending analysis; nothing auto-fetches before a user action.

**Tests.** Node tests cover two actual HTTP pagination boundaries in the browser adapter, all categories/unknown-time arithmetic, exact bearer/header exclusion from URLs, mid-pagination inconsistent totals, cancellation on bearer change, empty Case and absent token. Go test runs the Node tests when Node is installed (GitHub CI provides Node), and checks the embedded HTML/JS trigger. Existing Go HTTP integration tests exercise actual Case/Timeline/source owner permissions including cross-tenant and denied source. No new data endpoint or authorization authority was introduced.

**Limitations.** This is a local synthetic Case analyst workflow, **not a deployed multi-tenant SIEM**. It uses caller-supplied disk snapshot, process-local principals and no production identity/ACL provider or persistent search index. Paginated API reads are re-authorized per request but not transactionally isolated: counts are point-in-time best effort and may change under concurrent owner changes. Up to 25 GETs for 5,000 entries; no production throughput/SLO claim. OPEN-013 and canonical Shared Timeline Entry ownership remain unresolved.
