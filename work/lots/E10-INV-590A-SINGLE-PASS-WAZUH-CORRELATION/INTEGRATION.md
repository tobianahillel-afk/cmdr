# E10-INV-590A — Shared Wazuh observation pass for cross-Case investigation

## Purpose

An existing first-party offline Case investigation compares **two independently authorized**, fingerprint-verified synthetic Case owners. Its `compareLoadedAuthorizedSavedCases` builds two Wazuh correlation views from the same source data: counts by Wazuh rule/agent in common 5-minute bins, and navigable pairs within inclusive 60s. These two views previously each called `collectAuthorizedWazuhObservations` on each Case, repeating bounded Case entries/source classification and per-cohort timestamp sorting **four traversals per comparison**.

This change has **no new search engine, source parser, IAM, report type or intermediary file**. After the existing first-party complete Case/Timeline/typed-source authorization and tenant/environment checks, `compareLoadedAuthorizedSavedCases` collects the same Wazuh observations just ONCE for each already independently scoped owner. Two small computation helpers consume these immutable grouped/sorted observations to produce the **existing** 5-minute and <=60s lead structures. The former public standalone correlation functions remain compatible and simply delegate to the same helpers; direct consumers are not broken. No source or owner graph is combined; a pair ID remains a navigation selector, not permission.

## Security, evidence and performance contract

- **No authorization change:** Each of two original owner graphs is independently byte-checked (operator-held SHA-256), Case/tenant/environment/principal-scoped, and fully paginated with typed-source read ACL before Wazuh cohort collection. Generic JSONL events cannot become Wazuh cohorts and are not leaked to the private correlated pair report.
- **No new output:** Deterministic sorted 5-minute Wazuh rule/agent bins (max 10) and 60s per-event pairs (max 10), canonical smallest-ID tie break, and both individually authorized private source reopen paths retain the same serialized schemas and behavior. Temporal co-occurrence is not causality and synthetic operator-provided metadata is not cryptographic provenance.
- **Performance/simplicity:** Per complete verified comparison the two previous functions separately collected sorted Wazuh groups for both Case owners. Shared results reduce four such collection/sort calls to two. This is an architectural operation-count reduction, NOT a claim of 2× end-to-end speed or measured production throughput. Bounded <=5000 Case entries and unchanged 10 pair output.
