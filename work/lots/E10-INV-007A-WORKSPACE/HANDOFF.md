## Focused R2 corrective delta — independent Search Job navigation context

The original Class-0 workspace used the shared browser `openSource(entryID)` path. That path first validated the **independent Case Timeline** date filter, so a malformed/irrelevant Timeline date silently prevented the analyst from inspecting an otherwise authorized completed Search Job hit. It also copied unrelated Timeline `kind`/`q`/date return-context into the Search Job navigation. This is a reproducible product workflow defect, not an access-control vulnerability or authorization bypass.

The focused child patch adds a boolean *call-site origin* to the existing `openSource` function. Only validated, completed local Search Job hit controls pass the flag. They send the selected Case, canonical authorized Entry ID, and bounded paging context to the **same existing first-party** `/case-source-navigation` followed by independently authorized `/demo-source-open`, without inheriting Timeline-only return filters. Ordinary Timeline and independent non-SearchJob source links retain their previous behavior and require a valid Timeline selection. The existing end-to-end browser test now sets a deliberately invalid/unrelated Timeline date, kind and keyword, then verifies a completed-job selected result still follows both authorization routes, the navigation does not transmit those unrelated filters, source revocation is denied, and a rotated bearer renders old controls inert. No new API, IAM, storage, permission or vendor dependency.
