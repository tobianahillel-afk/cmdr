# E10-INV-101M-PAGE — Native authorized Case Queue HTTP pagination

**Canonical owner** CAP-INV-101 Investigate Case Queue; REQ-PROD-014/020, screen INV-CAS-001. **Non-owners**: Shared owns Saved Views, Command owns Incidents; Case Workspace consumes navigation but does not grant permissions. **Engineering parent** existing epic E10-INV-101, child of E10-INV-101L-VIEW IMPLEMENTED; the Git base is frozen PR #143 SHA `d30771735029bd21207357b0966c1ac0ccad7d9b` (not `main`). **Code owner** `product-runtime/case-queue`; no new architectural boundary.

## Canonical obligation → code → demonstration → remaining

CAP-INV-101 §§3/11/15/16/22 and first-party pagination/filtering/sorting contract require a navigable read-only list with freshness, search, Saved Views, deterministic sort, missing/partial states and bounded pagination. The native `NewAuthorizedQueueHTTPHandlerWithSavedViews` already reauthorizes Cases/Incidents/Findings and resolves Shared Saved View per GET/open/return, but GET always serialized the ENTIRE projected list (up to 5000 records), risking an over-4-MiB rejection. The first-party `ProjectWithSavedViewFallback` is reused unchanged.

**New opt-in GET** `/case-queue?status=investigating&sort=title:asc&limit=50` responds in the SAME existing JSON projection shape, with `rows` bounded to 50 and an optional `next_cursor` when additional authorized rows remain. A following request preserves filters/sort/limit and adds `cursor=<opaque>`. The cursor encodes only an offset, page-size and SHA-256 digest of the entire currently readable projection AND current trusted Shared Saved View (ID, version and element permissions); no Case ID, raw evidence, session token or Case contents. It is **not** a credential, cryptographic authorization token or immutable storage snapshot.

**Critical safety**: every GET page re-fetches the authenticated session and current Case candidates, reauthorizes every Case plus its Incident and Finding via the host, obtains the current Shared Saved View from the host and runs the SAME native projection before checking the cursor. A changed ACL, Saved View version, Case snapshot or source metadata affecting the projection results in a cursor mismatch, generic 404 and NO partial rows. Unchanged data produces deterministic ordering and continuing rows. Cursor contents may be tampered with but can only pick an offset inside CURRENT authorized rows; the hash prevents stale traversal. Snapshot-level consistency across concurrent mutations is not claimed; invalidation is the defined fail-closed behavior.

**Compatibility**: ordinary GET without paging flags is byte-shape-compatible with the prior projection; `GET ...open_case=...` and `POST /case-queue/return` retain existing fully reauthorized workspace transition/return, do not accept pagination fields. Unknown, duplicated, malformed or oversized controls are rejected before host/session reads. Page limit 1–100; existing global raw URL bound 4096 bytes, max 5000 candidate objects and 4 MiB response cap remain. Streams full projection to SHA256 rather than allocating a second full-list JSON copy.

## Tests / verification
