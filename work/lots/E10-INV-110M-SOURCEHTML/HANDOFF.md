## Behavior and limits
The existing synthetic memory source owner already has a bounded JSON GET /demo-source-open with independent session->Case->Timeline Entry->typed source->destination read decisions. This task adds `Accept: text/html` on that exact endpoint **after all existing authorizations**; it renders the identical bounded source preview into semantic HTML via Go html/template autoescaping. No new route/provider/permission, no search/Case/Evidence/Timeline mutation, no production data. Source type and object ID originate in trusted projection, not request parameters; the only allowed GET selectors remain exact case_id and entry_id. CSP denies scripts/frames/forms/external assets, and response is no-store, no-referrer, nosniff with Authorization+Accept variance. The original application/json response object and error statuses are unchanged; q=0 or malformed Accept does not select HTML.

HTML includes a fixed origin-relative Case Timeline link with only Case ID. That link re-reads the owner but **resets filters**; native browser Back restores the previous URL/filter/page when the source was opened from a browser timeline. The source is visibly described as SYNTHETIC, not independent forensic Evidence. HTML rendering does not create reliable audit, session, IAM, privacy clearance or a real source view for Wazuh.
